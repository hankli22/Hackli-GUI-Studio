本项目自身以 **GNU GPLv3** 发布，完整文本见仓库根目录的 [`LICENSE`](../LICENSE)
（**在发行包中，许可证文本是包根目录的 `LICENSE.txt`**）。

## 1. 问题的由来

GPLv3 第 2 节（Basic Permissions）末段写得很清楚：

> 运行程序所产生的输出，**只有当该输出的内容本身构成"受本许可证保护的作品"时**，
> 才受本许可证约束。

本工具会**生成源码**。因此关键在于：你导出的那份代码，与你用什么样的方式使用本项目，
决定了它是不是"受 GPLv3 保护的作品"。本项目的两种导出模式差别很大，请分开看待。

## 2. 运行时导出（Runtime）——涉及下游义务

运行时导出的产物包含：

- 一个 `com.hackli.guidesigner.runtime.UiScreen` 的子类（布局在代码里展开），
- 一个 handler 类（每个控件一个空方法 + 按 id 分派的回调）。

这份代码在编译期与运行期都**链接并依赖本 mod**（`UiScreen`、`UiRenderer`、`UiContainer`、
`UiCallbacks` 等），也就是说你的插件与本 mod 组成了一个整体运行的程序。
当你**分发**这个插件（以及随之分发的本 mod / 其接口依赖）时，
就落入了 GPLv3 第 4–6 节关于分发的条款：

1. **建议（也是最省事的做法）**：把你的插件以 **GPLv3** 发布 —— 随插件附带 GPLv3 全文
   （[`LICENSE`](../LICENSE) / 发行包中的 `LICENSE.txt`），并向你的用户提供对应源代码。
   Meteor Client 本身就是 GPLv3，这样做通常也不会带来额外的冲突。
2. 保留生成文件头部关于来源与许可证的说明注释。
3. 本 mod 作为运行时库与你的 GPLv3 插件一起分发是**兼容**的（双方均为 GPLv3）。

若你无法接受以 GPLv3 分发自己的插件，请改用下面的静态导出模式。

## 3. 静态导出（Static Meteor）——通常不涉及

静态导出的产物是一个自包含的 Meteor `WidgetScreen`：它只使用 Meteor Client 自己的控件
（`theme.button(...)`、`theme.section(...)` 等），**不引用 `com.hackli.guidesigner` 的任何类**，
运行时**不需要**本 mod。

在本项目看来，这是一份"用本工具产出的、自身完整且与本程序可分离"的代码，
把它一概认定为必须按 GPLv3 分发，属于对 GPL 的**过宽**解释。

不过，"是否构成衍生作品"最终取决于具体事实（你对生成代码做了多少修改、
它与本程序的关系、你是否同时分发了本项目的一部分等），因此：

- **本项目不对静态导出的许可证归属作绝对断言**；
- 如果你需要合规上的确定性，最稳妥的选择仍然是把插件以 GPLv3（或与之兼容的许可证）发布；
- 无论选择哪种许可证，请保留生成文件头部标明的来源与许可证说明注释，
  也不要移除 Meteor Client 或其它第三方文件中的版权声明。

## 4. 不产生分发义务的情形

- 仅在游戏内**使用**本工具设计界面、调整布局（`gui-layout-editor` 模块只是把 JSON 布局
  保存在**你自己的**客户端里），不产生 GPLv3 的分发义务；
- 只在内部使用、不向他人分发你的插件或其二进制，同样不产生分发义务。

义务产生于**分发**（发布插件 jar 或源码、随整合包分发、提供给他人使用等）之时。
